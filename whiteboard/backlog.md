# backlog

このファイルには、次回すぐには着手しない長期の残作業、問題点、保留事項を書く。
現在の状態と次回の作業再開に直接必要な項目は `NEXT.md`、今後も有効な仕様、設計判断、不採用理由、運用制約は `DECISIONS.md` に書く。
完了履歴や検証ログの保管場所にはしない。

## 残作業

- フル再生成比較の進め方を立て直す。再開時は
  `whiteboard-app/regeneration_alignment_plan.md` を起点に、仕様化前ノートと実装設計契約の
  役割を確認してから行う。三点セットを直接手編集しない。既存テストの通過だけでなく、
  現行実装との差分分類まで実施する。
- MCP 対応を Windows/MSVC で configure、build、Streamable HTTP と互換用標準入出力の接続まで
  確認する。外部 qtmcpserver へ依存しない構成で、Qt HttpServer と Qt Network が正しく配置されることを確認する。

## 問題点

- 通常保存・復元失敗の保護はSitesの1.3.0配布版から反映済み。今後の追加検証では、
  Windows実機、実ディスク満杯・媒体障害・電源断、保存停止中のGUI操作の組み合わせを区別する。
  自動テストの通過だけでこれらを確認済みとしない。バックアップ履歴の追加は別の判断とする。

## 保留事項

- ページ上限を変更する機能は、回答・仕様判断を一旦保留している。
  `whiteboard-app/prompts/page_limit_change_prompt_draft.md` にD01〜D10の回答例・得失評価と
  T01〜T14の受け入れ条件案を保存した。再開時の手順は `NEXT.md`、判断の状態は `DECISIONS.md` を参照。
  設定上限の数値、初期ページの置換など、1.3.0配布版にない案を自動採用しない。
  未決事項の整理と実装指示があるまで、コード・正式仕様・配布物は変更しない。

- 描画データのインポート／エキスポートと保存保護は1.3.0の正式source release ZIPへ反映済み。
  DMGやWindowsバイナリを追加配布する場合は、対象OSでの検証・再生成・案内更新の範囲を決める。
  過去の1.2.0 ZIPは別版として保持し、1.3.0の機能を含むものとして扱わない。
- 次回配布時はローカル確認用 `whiteboard-app.zip` と DMG を MCP 対応バイナリから再生成し、
  外部 qtmcpserver ライブラリなしで Qt HttpServer と Qt Network が含まれることを確認する。
  正式な source release ZIP 1.2.0 は作成・配布先配置済みで、検証結果を `NEXT.md` に記録している。
