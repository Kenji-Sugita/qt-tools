# verification -> foundation コンサルティング結果

## 対象

検証結果や運用上の課題をもとに、準備基盤と文書運用を整備する工程を対象とする。

## 要約

- AI は問題の再発防止策、文書更新箇所、テンプレート改善点の整理に向く。
- 人は運用ルール化、承認フロー、継続適用可能性の判断を担う。
- 自動化は中程度で、標準化案のたたき台作成に特に有効である。

## 入力

- 検証結果文書
- 既存運用ルール
- テンプレート群
- 問題記録

## 出力

- 基盤整備項目一覧
- 文書更新提案
- テンプレート改善案
- 運用ルール見直し案

## AI の役割

- 問題を工程別に分類する
- 再発防止のための文書修正候補を挙げる
- テンプレートや README 更新案を作る
- ルール変更の影響箇所を整理する

## 人の役割

- ルールとして採用する内容を決める
- 運用コストと効果の釣り合いを判断する
- チームに定着させる手順を設計する
- 更新内容を正式に承認する

## 適用条件

- 問題記録と検証結果が工程別に残っている
- 再発防止をテンプレートやルールへ戻す運用責任者がいる

## 非適用条件

- 不具合が個人作業で閉じていて、知見が共有されない
- 文書更新だけで運用改善が成立すると誤認している

## 自動化できる範囲

- 問題分類と原因候補整理
- 更新対象文書の洗い出し
- テンプレート改善案の下書き
- 変更影響範囲の整理

## 自動化しにくい範囲

- 組織運用に合うルールの最終選定
- 承認フローや責任分担の設計
- 継続運用できる粒度への調整

## Qt 固有の重点論点

- Qt 版差分や OS 差分で再発しやすい問題の分類
- `clazy`、`QTest`、`Squish for Qt` の運用ルール化
- `Qt Creator MCP server` をローカル支援に限定する運用整理

## 推奨 LLM / 使い分け

- 分析と要約に強いモデル
  - 問題分類と改善案整理に使う
- 厳密なレビュー向きモデル
  - 影響範囲と抜け漏れ確認に使う
- 低コストモデル
  - テンプレート更新案の反復に使う

## AI と既存自動化手段の役割分担

- AI
  - 問題分類、更新対象文書の洗い出し、改善案の下書きを担う
- `clazy` / `QTest` / `Squish for Qt`
  - 再発しやすい問題の検出結果や運用知見の入力源となる
- `Qt Creator MCP server`
  - ローカルの build / debug 文脈から運用改善に必要な観察材料を補う
- 人
  - ルール採用判断、運用定着、責任分担設計を担う

## プロンプト設計方針

- 問題、原因、対策、更新対象を分けて入力する
- 文書名を固定して影響箇所を列挙させる
- 即時対応と恒久対応を分離させる
- 採用判断が必要な案には理由を付けさせる

## 導入段階

- PoC
  - 1 件の障害からテンプレート更新までつなげる
- 限定導入
  - 工程別に再発防止の戻し先を固定する
- 本格導入
  - プロンプト集、失敗事例集、Qt 向けレビュー観点を継続更新する

## KPI

- 同種不具合の再発件数
- テンプレート更新反映までの時間
- 運用ルール逸脱件数

## 顧客提案時の訴求点

- 生成 AI を単発導入で終わらせず、運用改善までつなげられる
- 文書とテンプレートを整えることで継続的に精度を上げられる
- 人は運用ルールと承認に集中できる
