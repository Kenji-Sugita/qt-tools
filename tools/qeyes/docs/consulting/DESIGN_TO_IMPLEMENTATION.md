# design -> implementation コンサルティング結果

## 対象

詳細設計書から実装ファイルとビルド構成へ変換する工程を対象とする。

## 要約

- AI は設計書を採用した UI 技術方針に沿ったコードへ変換する支援に向く。
- 人は実装品質、ライブラリー利用妥当性、保守性、既存挙動との整合を担う。
- 自動化効果は高いが、生成コードの無批判な採用は避けるべきである。

## 入力

- 詳細設計書群
- 既存コード
- 既存ビルド設定
- 使用 Qt 版
- 対象 OS
- 既知不具合一覧
- コーディング規約
- 実装方針
- リソース運用方針
- ビルド方針

## 出力

- ソースコードのたたき台
- ビルド定義
- リソース参照定義
- 必要に応じて追加・更新した `QTest` / Squish スクリプト
- 実装上の注意点一覧

## AI の役割

- 詳細設計をクラス、関数、イベント処理へ写像する
- 採用した UI 技術方針に沿ったコード骨格を作る
- 必要に応じて描画処理のたたき台を作る
- 必要に応じた単体テストや GUI テストを追加・更新する
- 設計とコードの対応関係を説明付きで出す

## 人の役割

- コード品質と設計整合性をレビューする
- Qt API の適切な使い方を確認する
- プラットフォーム差分や例外動作を検証する
- リファクタと修正範囲を管理する

## 適用条件

- 詳細設計に Qt 版、使用モジュール、対象 OS が明記されている
- 既存コードや既知不具合を参照できる
- ビルド方法と使用 kit が分かっている

## 非適用条件

- 設計が未確定のままコード生成へ進む
- 既存コードと新規生成コードの責任分界が曖昧である

## 自動化できる範囲

- クラス骨格生成
- イベント処理や設定保存処理のたたき台作成
- ビルド定義の初期生成
- 必要に応じた `QTest` / Squish スクリプトの追加・更新
- 設計書とコードの対応表作成

## 自動化しにくい範囲

- 実動作を見た上での細かなチューニング
- パフォーマンスや描画品質の最終調整
- 既存コード規約や周辺事情を踏まえた構成最適化

## Qt 固有の重点論点

- `QObject` の所有権と親子破棄
- signal / slot 接続先の寿命と責務境界
- thread affinity を破らない UI 更新
- 採用した UI 技術に応じた描画責務と更新契機
- `QSettings` のキー、互換性、保存粒度
- `moc` / `uic` / `rcc` を含むビルド整合

## 推奨 LLM / 使い分け

- コーディング能力の高いモデル
  - 実装骨格と変更パッチ生成に使う
- 長文整合性に強いモデル
  - 設計書との一致確認に使う
- 低コストモデル
  - コメント整理や軽微な修正案に使う

## AI と既存自動化手段の役割分担

- AI
  - クラス骨格、イベント処理、差分パッチ案、設計とコードの対応表を作る
- `Qt AI Assistant`
  - Qt / QML に寄ったコード提案、レビュー、必要に応じた単体テストや補助コードの追加・更新を補助する
- `GitHub Copilot plugin for Qt Creator`
  - `Qt Creator` 上での入力補完や定型コード生成を補助する
- `Qt Creator MCP server`
  - `Qt Creator` 文脈で `build`、`run_project`、`debug`、`list_issues` を呼び、ローカル実装ループを補助する
  - ただし、リリースされたばかりの新しい機能であり、現時点では基本的な IDE 操作支援に用途を限定する
  - より高度なコード理解や IDE 連携は、将来の改良に期待する
- `clazy`
  - Qt 特有のアンチパターンや API 利用上の警告を検出する
- `clang-tidy`
  - C++ 全般の静的解析を担う
- 人
  - API 採用判断、保守性判断、例外動作の最終調整を担う

## プロンプト設計方針

- 設計書の該当節をコード生成対象ごとに分割入力する
- 使用技術、禁止技術、保存方針を固定条件として明示する
- 既存コードとの差分で出力させる
- 生成理由と未保証点を添えさせる
- ビルドエラーや `Qt Creator` の `Issues` を再投入して修正ループを短くする

## 導入段階

- PoC
  - 1 機能を対象にコード生成とビルド修正ループを検証する
- 限定導入
  - `Qt Creator MCP server` と静的解析を組み合わせて局所的に運用する
- 本格導入
  - 設計粒度、プロンプト、解析ルール、レビュー観点を標準化する

## KPI

- ビルド一発成功率
- `Qt Creator` の `Issues` 解消までの反復回数
- `clazy` / `clang-tidy` 指摘件数
- 設計との差分件数

## 顧客提案時の訴求点

- 実装初期工数を大きく削減できる
- 設計からコードへのトレーサビリティを持たせやすい
- 人は品質保証と最終調整に集中できる
