# qeyes / seminartimer 人手開発工数見積もり

前提を置いて見積もると、**アプリ本体 + CMake ビルド設定 + 最低限のパッケージング/手動確認**で、だいたい次くらいです。

根拠としては、主要コードが `qeyes/main.cpp` 440行、`seminartimer/main.cpp` 584行で、どちらも `QPainter` ベースのカスタム描画、フレームレス/透過ウィンドウ、入力処理、設定保持を含んでいます。単純な LOC より少し重いタイプです。

`1人日 = 8時間` とします。

| Qt知見レベル | qeyes | seminartimer | 合計 |
|---|---:|---:|---:|
| 上級 | 1〜2人日 | 2.5〜4.5人日 | 3.5〜6.5人日 |
| 中級 | 2〜4人日 | 5〜8人日 | 7〜12人日 |
| 初級 | 5〜8人日 | 9〜15人日 | 14〜23人日 |

レベル感はこうです。

- 上級: Qt Widgets / `QPainter` / フレームレスウィンドウ / `QSettings` / CMake / macOS バンドルに慣れている人
- 中級: Qt アプリは作れるが、カスタム描画や macOS 固有のウィンドウ挙動は調べながら進める人
- 初級: C++ は書けるが Qt 実務は浅い人

補足です。

- `qeyes` は見た目は小さいですが、透過描画、視線追従計算、色設定ダイアログ、設定永続化が入っているので、サンプルアプリよりは重いです。
- `seminartimer` はカスタム UI、状態遷移、点滅、通知音、キーボード操作、設定ダイアログがあり、こちらの方が明確に工数が大きいです。
- `qeyes/docs` 以下の大量ドキュメントや派生 ZIP/DMG まで人手で同じ密度で再現するなら、特に `qeyes` はさらに数人日上乗せになります。そこは AI で膨らんでいる部分で、通常の人手開発ならここまで文書は作らないはずです。

実務感に寄せて一言で言うと、**人が AI なしで作るなら、上級者で 1週間弱、中級で 1.5〜2.5週間、初級なら 3〜5週間くらい**が目安です。
