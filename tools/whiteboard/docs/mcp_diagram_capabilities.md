# MCP 対応ホワイトボードで作成できる図

## この文書について

この文書は、WhiteboardApp 内蔵の MCP Server で、AI から図形作成用の MCP tool を
呼び出して作成できる図と表現上の制約を説明する。

WhiteboardApp を通常起動すると、`http://127.0.0.1:8765/mcp` で Streamable HTTP
MCP Server が開始される。MCP クライアントは起動済みアプリへ URL で接続する。
`--mcp` による標準入出力接続も互換用として利用できる。

`/mcp` は JSON-RPC の POST を受け付ける endpoint である。GET の SSE ストリームは提供しないため、
`curl -i http://127.0.0.1:8765/mcp` のような GET 確認では `405 Method Not Allowed` が返る。
これは正常応答であり、疎通確認は `Content-Type: application/json` と
`Accept: application/json, text/event-stream` を付けて `initialize` を POST して行う。

## 作成方法

利用者は、作成したい図を自然言語で AI に指示する。
AI は指示を図形、座標、テキスト、色、線、グループなどのデータへ変換し、
WhiteboardApp の MCP tool を呼び出す。
Codex など複数の出力手段を持つクライアントへ指示する場合は、
「WhiteboardApp の MCP ツールを使う」「HTML や visualize は使わない」と明示すると、
別の可視化ファイルを作る誤動作を避けやすい。

想定する処理は次のとおり。

1. AI がページ数、現在ページ、キャンバスサイズ、ロック状態を取得する。
2. AI が図の構成とレイアウトを決める。
3. AI が一回の操作でページと図形をまとめた要求を送る。
4. WhiteboardApp が変更内容を表示し、利用者へ実行確認を求める。
5. 許可された場合だけ、図を画面へ反映して保存する。
6. AI が作成ページの PNG を取得し、配置や文字の収まりを確認する。
7. 必要に応じて永続 ID を指定し、既存要素だけを更新または削除する。

作成された図は通常のホワイトボードオブジェクトであり、作成後はマウスとキーボードで
移動、リサイズ、回転、テキスト編集、色変更、グループ化などを行える。

公開 tool は、状態・要素一覧、永続 ID による要素更新・削除、ページ一覧、ページ移動・追加・
削除・ロック、統合要素変更、図反映、現在ページ PNG、PNG/SVG の取得・保存、Undo/Redo の 16 件である。
図反映は新規ページ、現在ページへの追加、現在ページの置換に対応する。既存図はページ全体を
作り直さず、`whiteboard/elements/update` と `whiteboard/elements/delete` で部分修正できる。
追加・更新・削除を一度に行う場合は `whiteboard/elements/apply` を使う。要素一覧で取得した
`revision` を `expectedRevision` として渡し、その間に別の変更があった場合は要求全体が拒否される。

## 業務と手順の図

### フローチャート

処理、判断、開始、終了、分岐を図形と矢印で表現する。

例:

- 申請から承認までの業務フロー
- データ入力、検証、保存、エラー処理
- 問い合わせ受付から回答までの流れ
- 障害発生時の対応手順

指示例:

> 入力、検証、変換、JSON 保存の 4 段階で処理フローを作成してください。
> 正常処理は緑、エラー処理は赤の矢印にしてください。

### 業務プロセス図

担当者や部門ごとに処理を分け、受け渡しと順序を示す。

例:

- 営業、技術、経理をまたぐ受注処理
- セミナーの企画、募集、開催、フォローアップ
- レビュー、修正、承認、公開の工程

### 状態遷移図

状態を角丸長方形、遷移を矢印、条件をテキストで表現する。

例:

- 未保存、編集中、保存済み
- 待機中、実行中、成功、失敗
- 申請前、申請中、承認済み、差し戻し

### タイムラインとロードマップ

時間軸に沿って予定、イベント、マイルストーンを配置する。

例:

- 開発スケジュール
- 製品リリース計画
- セミナー準備日程
- 障害発生から復旧までの経過

## ソフトウェア設計の図

### システム構成図

アプリケーション、サービス、データベース、外部システムなどの構成要素と接続関係を示す。

例:

- デスクトップアプリと保存ファイルの関係
- クライアント、API、データベースの 3 層構成
- MCP クライアント、WhiteboardMcpController、BoardModel の接続構成

### アーキテクチャ図

責務ごとの層、モジュール、依存方向を表現する。

例:

- UI、アプリケーションロジック、モデル、永続化のレイヤー
- Qt Widgets アプリケーションのクラス責務
- プラグインとホストアプリケーションの関係

### データフロー図

データの入力元、変換処理、保存先、出力先を矢印で結ぶ。

例:

- JSON ファイルの読み込みと保存
- ユーザー操作から描画更新までの流れ
- AI の指示から MCP tool 実行までの流れ

### モジュール依存図

ライブラリ、実行ファイル、テスト、外部依存の関係を示す。

例:

- WhiteboardApp、WhiteboardCore、WhiteboardPlatform の依存関係
- アプリケーション内蔵 MCP Server と GUI / Core の依存構成
- ビルドターゲットとテストターゲットの構成

### クラス図の簡易版

クラス名、主な責務、主要な関連を矩形と線で示す。
厳密な UML 記法の検証は行わないが、設計説明用のクラス関係図を作成できる。

### ER 図の簡易版

エンティティ名、主要属性、エンティティ間の関係を表現する。
カーディナリティは線端の文字や記号で示す。

### シーケンス図の簡易版

参加者を横方向、時間を縦方向に配置し、メッセージを矢印で表現する。
ライフラインやメッセージ順を説明する静的な図を作成できる。

### ネットワークと配置構成図

端末、サーバー、ネットワーク境界、配布先などを図形で表現する。

例:

- 開発端末と CI サーバー
- macOS、Windows、Linux 向けの配布構成
- アプリケーション、共有ライブラリ、Qt Framework の配置

## 情報整理と検討の図

### マインドマップ

中心テーマから関連項目を放射状または階層状に配置する。

### 組織図と階層図

組織、チーム、機能、ディレクトリなどの親子関係を表現する。

### 比較表とマトリクス

複数案を行と列で比較する。

例:

- 技術選定比較
- 機能と対象ユーザーの対応表
- Qt の QSizePolicy 比較
- リスクと対策の一覧

### 2 軸マップと 4 象限図

重要度と緊急度、効果とコストなど、2 つの評価軸で項目を分類する。

### SWOT 分析

強み、弱み、機会、脅威を 4 区画に分けて整理する。

### 課題整理図

課題、原因、影響、対応策をグループごとに配置して関連線で結ぶ。

### 付箋形式のアイデアボード

短いテキストを色分けした矩形へ配置し、テーマや優先度ごとにまとめる。

## 画面設計の図

### デスクトップアプリのワイヤーフレーム

ウィンドウ、ツールバー、サイドバー、入力欄、ボタン、一覧、ステータス領域などを配置する。

### Qt Widgets の画面案

例:

- QToolButton
- QLineEdit
- QTextEdit
- QComboBox
- QCheckBox
- QRadioButton
- QSlider
- QProgressBar
- QTabWidget
- QGroupBox
- QListView
- QTreeView
- QTableView

### ダイアログと設定画面

ラベル、入力欄、選択肢、確認ボタンを整列させたフォームを作成する。

### 画面遷移図

各画面を縮小した矩形で表現し、操作による遷移を矢印で結ぶ。

## 使用できる表現要素

MCP から既存の WhiteboardApp の機能を利用することで、次を指定できる。

- 直線と矢印
- 図形に追従するコネクター直線
- 折れ線と閉じた折れ線
- ベジェ曲線
- 長方形と角丸長方形
- 円と楕円
- 円弧
- 単一行および複数行テキスト
- 線色と塗り色
- 文字色とフォント
- 線幅、実線、点線
- 始点と終点の矢印
- 直線端点の接続先 ID
- オブジェクトの回転
- オブジェクトのグループ化
- 前面、背面などの重なり順
- 反映後の各描画要素には WhiteboardApp が永続 ID を付与し、`whiteboard/state` で取得できる
- `whiteboard/diagram/apply` の入力要素には一時参照用の `id` を指定できる。直線要素では
  `startConnectionElementId` と `endConnectionElementId` で接続先を指定でき、反映後は
  WhiteboardApp が採番した永続 ID へ張り替える

キャンバスの論理サイズは 1920 x 1080 とし、AI はこの範囲内へ全オブジェクトを配置する。

## AI による確認と修正

図形データだけでは、文字の収まりや視覚的なバランスを完全には判断できない。
そのため、作成後のページを PNG として AI に返し、次の点を確認できる構成とする。

- オブジェクトがキャンバス外へ出ていないか
- テキストが図形からはみ出していないか
- 図形同士が不自然に重なっていないか
- 間隔と整列が一貫しているか
- 矢印と接続先が分かりやすいか
- 色と文字のコントラストが十分か
- 図全体の余白が適切か

修正時はページ全体を置換するか、現在ページへオブジェクトを追加する。
一回の AI 更新を一回の Undo として扱い、利用者が変更前へ戻せるようにする。

## 制約

作成される図は、WhiteboardApp の図形を配置した静的なベクター図である。
専用の UML、ER、フローチャートエンジンではないため、次の機能は自動ではない。

- 図形追加後の継続的な自動レイアウト
- 線の自動迂回と交差回避
- UML 記法や ER 図カーディナリティの意味検証
- シーケンス図の実行意味検証
- Mermaid、PlantUML、Graphviz との双方向同期
- 画像、写真、動画の配置
- 3D 図形
- 表計算データと連動するグラフ
- 個別オブジェクト ID を指定した部分更新や削除

AI はこれらに似た見た目の静的な図を作成できるが、専用形式としての意味や自動更新機能は持たない。

## 適さない用途

次の用途は、現行の WhiteboardApp の図形機能だけでは適さない。

- 厳密な UML モデルを生成してコード生成へ使う用途
- 大規模な回路図や CAD 図面
- 数百から数千ノードのネットワーク可視化
- データに連動して自動更新されるダッシュボード
- 写真や画像素材を中心としたデザイン
- ピクセル単位の完成画面デザイン

このような用途では専用ツールで元データを作り、WhiteboardApp は説明、検討、注釈、
セミナー表示などに利用する。

## まとめ

MCP 対応後の WhiteboardApp は、AI の自然言語指示から、説明図、業務フロー、
ソフトウェア設計図、情報整理図、Qt Widgets のワイヤーフレームを作成できる。

特に、オンラインセミナーや設計レビューで使う、見やすく編集可能な静的図の作成に適している。
AI が初期配置と視覚確認を担当し、利用者が最終調整と承認を行う使い方を基本とする。
