# リリース方針メモ

## 基本方針

最初のリリースは `Qt Cling CLI` とする。

この段階では、価値の中心を IDE 統合ではなく次に置く。

- Qt GUI を動かしたまま Cling で対話できること
- 最小サンプルをすぐ試せること
- Qt / C++ 初学者でも学習を始めやすいこと
- ドキュメントとチュートリアルを育てやすいこと

また、この製品はアプリケーション全体を動かす用途よりも、部品単位の試行と確認を速くする
用途に向いている。
特に、ウィジェット開発、ウィジェットの UI 調整、小さな挙動確認や再現実験が主な適用対象となる。

`Qt Creator` 対応はその後の段階で行う。
位置づけとしては、本体機能の置き換えではなく `Qt Cling CLI` の導線を IDE 内に持ち込む拡張。

## この順番にする理由

- まず製品の核を単独で成立させやすい
- Qt Creator プラグインより実装と保守が軽い
- サンプルやドキュメントを CLI 前提で先に整備できる
- 実利用を通して、Qt Creator 側で本当に必要な機能を見極めやすい

## 段階的なロードマップ

### 第1段階: Qt Cling CLI

初回リリースでは次を重視する。

- 起動スクリプト
- 最小サンプル集
- 学習順に並んだドキュメント
- トラブルシュート

この段階で今後詰めるべき主な項目は次の通り。

- Windows での対話実行対応
- Windows ネイティブ対応
- 現在のウィジェット中心サンプルに加えた QML 向けサンプル整備
- 起動スクリプトと補助ツールのリファクタリングおよび自動化
- ハードコーディングされたパスの排除とインストール対応

この段階では、プロパティーエディターは experimental な開発支援ツールとして扱う。

### 第2段階: Qt Creator 対応

Qt Creator 対応の最初の形は、重い統合ではなく薄い統合でよい。

- 現在のプロジェクト設定で `Qt Cling CLI` を起動する
- サンプルを IDE から開いて実行する
- ドキュメントから例を REPL に送る

つまり初期の Qt Creator プラグインは、独自機能の塊ではなく `Qt Cling CLI` のフロントエンドと考える。

### 第3段階: 学習体験の拡張

CLI と Qt Creator 統合が安定した後に、次のような機能を追加する余地がある。

- Step-by-Step tutorial
- Live Object Explorer
- Property Playground
- REPL history から `.cpp` 生成

## 位置づけの整理

要するに、進め方は次の順が自然。

1. 製品を作る
2. IDE に載せる
3. 学習体験を厚くする
