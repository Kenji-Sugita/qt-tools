# 作業管理ファイル共通運用ルール

## 適用範囲

`NEXT.md`、`DECISIONS.md`、`backlog.md` を読む、または更新するときに、このルールを適用する。

- `NEXT.md` の読み込みを依頼された場合は、`DECISIONS.md` と `backlog.md` も読み込み、3つのファイルから作業状態を把握する。読み込みだけの依頼ではファイルを変更しない。
- `NEXT.md` の更新を依頼された場合は、`DECISIONS.md` と `backlog.md` も読み込み、3つのファイルを現在の作業状態に合わせて必要に応じて更新する。以下の確認、分類、更新、検証、報告までを行う。
- 利用者は `DECISIONS.md` と `backlog.md` を依頼文に列挙しなくてよい。

## 更新前の確認

更新前に、Git の差分、直近のコミット、3つの作業管理ファイル、および関連文書を確認する。
既存の未コミット変更を保護し、依頼と無関係なファイルは変更しない。

## 情報の分類

- 現在の状態、次回やること、次回再開に必要な手順と注意事項は `NEXT.md` に書く。
- 次回すぐには着手しない長期の残作業、問題点、保留事項は `backlog.md` に書き、必要に応じて `NEXT.md` から参照する。
- 今後も有効な仕様、採用した設計判断、その理由、不採用理由、未決論点、判断基準、運用制約は `DECISIONS.md` に書き、必要に応じて `NEXT.md` から参照する。

`NEXT.md` の日付付きの作業記録は、直近 5 実作業日以内、または現在の作業テーマが完了するまでを目安とする。
実作業日とは、そのリポジトリで実際に作業、判断、検証、またはコミットを行った日を指す。
セッション数や暦日だけでは区切らない。
この期間制限は作業履歴にだけ適用し、現在も有効な仕様、設計判断、不採用理由、運用制約には適用しない。

## 情報の保護

情報を日付、行数、古さだけを理由に削除しない。
完了履歴や検証ログを削除する場合は、同じ情報が `CHANGELOG.md`、`README.md`、または特定できる Git コミットに残っていることを確認する。
今後の判断へ影響する結論、理由、制約は、削除前に追跡済み文書へ保存する。
保存先がない場合は、削除する前に適切な文書へ移す。

セクション単位の削除、複数の独立項目の削除、設計判断や不採用理由の削除、大幅な再構成が必要な場合は、まだ変更しない。
対象、理由、移動先を提示し、事前に利用者の承認を得る。
それ以外の情報の追記、項目の移動、現在の状態への修正は通常更新として実施する。

## 更新後の確認と報告

更新後は差分を確認し、可能なら `git diff --check` を実行する。
最後に、`NEXT.md`、`DECISIONS.md`、`backlog.md` の変更内容と検証結果をファイル別に報告する。

このルールは、ユーザーから明示的な指示がない限り変更しない。
