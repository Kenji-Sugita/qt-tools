# tl 仕様

最終更新日: 2026-04-22

## 概要

`tl` は、日本語と英語を自動判定して相互翻訳するコマンドラインツールです。

- 入力が日本語なら英語へ翻訳する
- 入力が英語なら日本語へ翻訳する
- 利用する翻訳エンジンは現時点では Google Cloud Translation
- 対応言語は `ja` と `en` のみ
- 実装は Qt ベースで行う

初版では自動判定を優先し、オプションは最小限に絞ります。

## コマンド名

```bash
tl
```

## usage

```bash
tl [text]
tl --file <path>
tl --help
tl --version
```

## オプション

- `--file <path>`
- `--help`
- `--version`

初版では次のオプションは持たせません。

- `--from`
- `--to`
- `--stdin`

## 入力仕様

入力ソースは次の優先順位で 1 つだけ使います。

1. 位置引数 `text`
2. `--file <path>`
3. 標準入力

詳細は次の通りです。

- 位置引数が 1 個ある場合は、その文字列を翻訳対象にする
- `--file <path>` が指定された場合は、ファイル内容全体を翻訳対象にする
- 位置引数も `--file` もない場合は、標準入力を EOF まで読む
- 標準入力は 1 行でも複数行でもよい
- 空入力はエラーにする

入力ソースは 1 つだけに制限します。

- 位置引数と `--file` の併用はエラー
- `--file` 指定時に標準入力も与えた場合はエラー
- 位置引数は 0 個または 1 個のみ許可する
- 位置引数が 2 個以上ある場合はエラー

## 標準入力仕様

- 引数なしで `tl` を実行した場合は標準入力を読む
- パイプ入力に対応する
- 複数行入力に対応する
- 複数行は入力全体を 1 テキストとして翻訳APIへ送る
- 出力時の改行保持は保証しない

例:

```bash
echo "今日は会議があります。" | tl
```

```bash
cat memo.txt | tl
```

```bash
tl
今日は会議があります。
資料はあとで送ります。
^D
```

## 自動判定仕様

- 言語判定は Google Cloud Translation の自動判定を使う
- 判定結果が `ja` なら翻訳先は `en`
- 判定結果が `en` なら翻訳先は `ja`
- 判定結果が `ja` / `en` 以外ならエラー
- 日本語と英語が混在する場合は、API が返した単一の検出言語に従う

## 出力仕様

- 成功時は翻訳結果のみを標準出力へ出す
- 余計な説明文は出さない
- 複数行入力に対して複数行出力になる可能性はある

## エラー仕様

次の場合は標準エラー出力にメッセージを出し、非 0 で終了します。

- 入力が空
- 位置引数が 2 個以上ある
- 位置引数と `--file` を同時に指定した
- `--file` 指定時に標準入力も与えた
- ファイルが読めない
- 認証情報が見つからない
- API 呼び出しに失敗した
- 自動判定結果が `ja` / `en` 以外だった
- API レスポンスが不正

## 利用例

```bash
tl "今日は会議があります。"
```

```bash
tl "Please check this file."
```

```bash
echo "この問題はまだ解決していません。" | tl
```

```bash
tl --file input.txt
```

## 環境前提

- Google Cloud Translation API を有効化済みであること
- Billing Account が設定済みであること
- `GOOGLE_APPLICATION_CREDENTIALS` が設定済みであること
- `openssl` コマンドが利用可能であること

## 実装前提

- 実装言語は C++
- 実装基盤は Qt とする
- コマンドライン引数解析は Qt の機能で行う
- 翻訳エンジン呼び出しはプロバイダ抽象を介して行う
- 現在の実装は Google Cloud Translation を使う
- 将来的に DeepL などを追加する場合も、対象は `ja <-> en` の範囲に限定する
