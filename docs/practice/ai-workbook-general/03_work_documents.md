■ 仕事の資料を作成・更新する：AIへの頼み方

「まず試してみる：AIへの頼み方」で試したことを、仕事の資料の作成・更新に使ってみましょう。お知らせ、会議資料、手順書、活動報告などを例に、繰り返し使える作業を練習します。

■ 最初は一つだけ試す

最初に読むのは、下の操作手順、「資料の役割を分ける」、選んだ一例、末尾の「今回の練習の完了基準」です。他の例と、業務への置き換え方は、必要になったときに読めます。

・短い案内文を作りたい → 【1】元資料から短い説明文を作る
・古い日時や情報を直したい → 【2】既存資料の日程や情報を更新する
・長い説明の概要が欲しい → 【3】詳しい説明を要約する
・決まった内容を追記したい → 【4】既存資料に新しい項目を追加する
・複数の記録の書き方をそろえたい → 【5】複数の情報を同じ形式にまとめる
・共有前の資料を確かめたい → 【6】完成した資料を元資料と照合する

迷ったら【1】を選び、内容を自分で確認できる短い元資料を一つ用意します。読む人と目的を一文で書き、書き方の見本は「見本なし」で始められます。材料がない場合は、先に01の架空のお知らせで試してください。

依頼文の使い方と、文章やファイルをAIへ渡す方法は「まず試してみる：AIへの頼み方」と同じです。

1. 使いたい依頼例を選びます。
2. 【AIへの依頼文：ここから】と【AIへの依頼文：ここまで】の間を、AIの入力欄へコピーします。
3. 「この行を削除し」と書かれた行を、指定された文章や情報に置き換えます。
4. 内容を確認して送信します。

長い文章はファイルでも渡せます。その場合は、01の「補足：ファイルをD&Dする場合」を参照し、ファイル名と役割を伝えてください。社外秘情報や個人情報などは、所属組織のルールに従って扱ってください。

■ 資料の役割を分ける

今回の練習では、資料を次のように分けて使います。それぞれの例に書かれた資料を用意してください。

・作成・更新する対象：追記したり、書き換えたりする資料です。
・書き方の見本：見出し、文章量、形式の参考にする資料です。見本にある古い日程や別の案件の内容を、今回の情報として使うものではありません。
・内容の根拠となる元資料：確定した案内、承認済みの手順、活動記録など、今回の記述を確かめるための資料です。

最初は、元資料の本文を貼り付けるか、ファイルで渡して試してください。URLだけを渡しても、AIがリンク先の本文を読み取れるとは限りません。

選んだ例の結果が出たら、その例の「どこを見るか」で元資料と比べ、末尾の完了基準へ進みます。確認の途中で止まる場合は、選んだ例の番号、使った資料、未確認の箇所、次に確認する相手を残してください。

【1】元資料から短い説明文を作る

● どのようなときに使うか

新しい社内サービスの案内など、詳しい資料を基に、読む人に必要な内容を短く伝えたいときに使います。まず説明文だけを作り、確認してからお知らせや会議資料へ入れます。

読む人と伝える目的、元資料を用意します。書き方を合わせたい場合は、過去のお知らせなどの見本を一つ用意してください。

● どのように依頼するか

【AIへの依頼文：ここから】

以下の元資料を基に、短い説明文を作ってください。
「読む人と目的」に合わせ、見出しと、3〜5文の説明にしてください。
何についての案内か、読む人にどう関係するか、何を知っておく必要があるかを、元資料の範囲で伝えてください。
元資料にない効果や評価は加えず、日付、数字、固有名詞、適用条件は正確に扱ってください。
見本は文章量と書き方の参考にだけ使い、見本の内容を今回の情報として使わないでください。
説明に必要な情報が不足している場合は、推測せず、説明文とは別の確認事項にしてください。

【読む人と目的：ここから】

この行を削除し、誰が読むか、何を理解してほしいかを入れてください。例えば「社内サービスを初めて使う社員に、利用できることと申請方法を知ってほしい」のように書きます。

【読む人と目的：ここまで】

【元資料：ここから】

この行を削除し、説明の根拠となる案内や資料の全文を入れてください。

【元資料：ここまで】

【書き方の見本：ここから】

この行を削除し、見本を一つ入れてください。見本がなければ「見本なし」と書いてください。

【書き方の見本：ここまで】

【AIへの依頼文：ここまで】

● どこを見るか

何の案内か、読む人にどう関係するかが分かるかを確認します。元資料と比べ、意味や条件が変わっていないか、見本の内容が混ざっていないかも見てください。

● なぜこのように頼むのか

元資料だけを渡すと、どこを重点的に説明するかが伝わりません。読む人と目的を添え、根拠と見本を分けて渡すことで、必要な内容と書き方をそれぞれ指定できます。

【2】既存資料の日程や情報を更新する

● どのようなときに使うか

前回の会議案内を使い、今回の日程や場所に更新したいときなどに使います。更新する資料と確定した最新情報、変更してよい項目を用意します。

● どのように依頼するか

【AIへの依頼文：ここから】

以下の既存資料を、確定した最新情報に基づいて更新してください。
変更してよい項目は、会議名、日時、開催場所、参加方法です。
今回の情報が確認できない項目は推測で更新せず、未確認として示してください。古い情報を、そのまま今回も有効な情報として扱わないでください。
それ以外の本文は変更せず、最新情報と食い違う場合は確認事項として示してください。
更新後の資料、変更した項目と変更前後の内容、残った確認事項の順に示してください。

【既存資料：ここから】

この行を削除し、更新する会議案内の全文を入れてください。

【既存資料：ここまで】

【確定した最新情報：ここから】

この行を削除し、今回の会議名、年月日と時間、開催場所、参加方法の確定情報を入れてください。

【確定した最新情報：ここまで】

【AIへの依頼文：ここまで】

● どこを見るか

日付や時刻、場所、会議への参加方法が最新情報と合っているかを一つずつ確認します。古い情報が残っていないか、変更対象以外の説明が書き換わっていないかも確認してください。オンライン会議のリンクは、文字列の照合に加えて実際に開いて確かめます。

● なぜこのように頼むのか

「今回の情報にして」だけでは、変える範囲や、何が確定しているかが曖昧です。更新元と更新対象、変更する項目を分けると、意図しない書き換えや古い情報の流用を減らせます。

別の資料に使う場合は、依頼文の「会議名、日時、開催場所、参加方法」を、その資料で更新する項目に置き換えてください。

【3】詳しい説明を要約する

● どのようなときに使うか

手順書の冒頭に概要を付けたり、長い説明を会議資料向けに短くまとめたりしたいときに使います。ここでは、詳しい手順書へ進む前に全体像をつかむための概要を作ります。

● どのように依頼するか

【AIへの依頼文：ここから】

以下の手順書の冒頭に載せる概要を、5項目以内の箇条書きで作ってください。
読む人は、この作業を初めて担当する人です。目的、対象者、作業の大きな流れ、始める前に必要な条件、重要な注意点を、元の手順書に書かれた範囲でまとめてください。
概要だけで作業を完了できるように見せず、実際の操作は手順書の本文で確認することを明記してください。
適用条件や例外を省くと意味が変わる場合は残し、指定の項目数に収まらない場合は、その理由を示してください。
元の手順書にない操作や条件は加えないでください。

【手順書：ここから】

この行を削除し、概要を付けたい手順書の全文を入れてください。

【手順書：ここまで】

【AIへの依頼文：ここまで】

● どこを見るか

作業の目的と流れが伝わるか、必要な条件や注意点が抜けていないかを本文と比べます。概要を読んだ人が、誤った順序や条件で作業を始めないかも確認します。

● なぜこのように頼むのか

要約する目的によって残す情報は変わります。概要として読むことと、操作の手順として使うことを区別すると、必要な条件を守りながら短くできます。

【4】既存資料に新しい項目を追加する

● どのようなときに使うか

会議資料や活動報告に、新たに決まった内容を追加したいときに使います。ここでは、活動報告の「今後の予定」に、新しく決まった作業を一つ追加します。

● どのように依頼するか

【AIへの依頼文：ここから】

以下の活動報告の「今後の予定」の末尾に、追加情報を基にした項目を一つ追加してください。
作業内容、担当、期限を、追加情報に書かれた範囲で簡潔に記載してください。
担当や期限が未定の場合は、勝手に決めず「未定」としてください。
既存の見出しと書き方に合わせ、目次や番号がある場合は追加に伴う調整をしてください。
同じ作業がすでに書かれている場合や、「今後の予定」が見つからない場合は、追加せず知らせてください。
既存の本文は番号などの整合の調整以外は変更しないでください。
修正後の全文、変更点、確認事項の順に示してください。

【活動報告：ここから】

この行を削除し、作成途中の活動報告の全文を入れてください。

【活動報告：ここまで】

【追加情報：ここから】

この行を削除し、新しく決まった作業内容、担当、期限の情報を入れてください。未定の項目は、そのことを記載してください。

【追加情報：ここまで】

【AIへの依頼文：ここまで】

● どこを見るか

追加内容が決定事項と合っているか、担当や期限が作られていないかを確認します。内容の重複、目次や番号の食い違い、既存の説明への意図しない変更も見てください。

● なぜこのように頼むのか

項目を追加すると、番号や全体の構成にも影響します。追加位置と変更範囲を伝えると、元の内容を保ちながら追記できます。

【5】複数の情報を同じ形式にまとめる

● どのようなときに使うか

複数の担当者から届いた進捗メモを、会議で確認しやすい形式へそろえたいときなどに使います。今回まとめる対象として選んだメモを、担当者や作業ごとに分けて用意します。

● どのように依頼するか

【AIへの依頼文：ここから】

以下の進捗メモを、会議で確認するために同じ形式にそろえてください。
作業ごとに「作業名／担当／報告時点／現在の状況／課題／次に行うこと／期限」の順でまとめてください。
書かれていない項目は「記載なし」とし、担当や期限を推測しないでください。
作業名、日付、数字、固有名詞は元のメモの表記を保ってください。
同じ作業と思われるメモでも、勝手に統合しないでください。内容の重複や食い違いがあれば、確認事項として示してください。
それぞれの項目の末尾に、元のメモの名前を添えてください。

【進捗メモ：ここから】

この行を削除し、今回まとめるメモを、メモ名と報告者が分かるように区切って入れてください。

【進捗メモ：ここまで】

【AIへの依頼文：ここまで】

● どこを見るか

元のメモと一つずつ比べ、作業の抜けや別の担当者の情報の混入がないかを確認します。報告時点の違いが残っているか、「検討中」が「決定済み」になるなど、状況の意味が変わっていないかも見てください。

● なぜこのように頼むのか

形式がそろうと比較しやすくなりますが、情報のない欄をAIが補うと、実際の状況とは違う報告になります。欠けた情報を残し、元のメモへ戻れるようにしておくと、必要な確認ができます。

【6】完成した資料を元資料と照合する

● どのようなときに使うか

お知らせ、会議資料、手順書、活動報告などを仕上げ、共有前に内容の抜けや食い違いを確認したいときに使います。完成案、作成に使った元資料、必ず入れる予定だった項目を用意します。

● どのように依頼するか

【AIへの依頼文：ここから】

以下の完成案を、記載予定の項目と元資料に照らして確認してください。

・必要な項目の抜けや重複がないか
・古い情報や、対象外の情報が混ざっていないか
・日付、数字、固有名詞、担当、期限、URLが元資料と合っているか
・要約や言い換えで、意味、条件、決定・未決の区別が変わっていないか
・見出し、目次、番号に食い違いがないか
・未記入の箇所や作成者向けのメモが残っていないか

結果は「確認した項目／判定（一致・不一致・確認できない）／元資料の根拠／修正案」に分けてください。
資料にないことは推測せず「確認できない」としてください。
URLの文字列が一致することと、リンク先を実際に開けることは分け、開いていないリンクは「アクセス未確認」としてください。
まず確認結果だけを示し、完成案は書き換えないでください。

【完成案：ここから】

この行を削除し、共有前の資料の全文を入れてください。

【完成案：ここまで】

【記載予定の項目：ここから】

この行を削除し、必ず入れる予定だった項目と、対象とする期間や業務の範囲を入れてください。

【記載予定の項目：ここまで】

【元資料：ここから】

この行を削除し、作成に使った案内、承認済みの手順、活動記録などを、資料名で区切って入れてください。

【元資料：ここまで】

【AIへの依頼文：ここまで】

● どこを見るか

AIが示した根拠を、自分でも元資料と照合します。「一致」でも確認を省かず、「確認できない」は担当者や正式な資料で確かめます。URLも実際に開いて確認してください。

ここで確認できるのは、渡した資料との一致と文章内の整合です。元資料そのものが最新か、手順や説明が実際の業務に合っているかは別に確認します。文章を直した後は、実際に共有するメール、PDF、スライドなどでも、改行や文字の大きさ、リンクなどを確認してください。

● なぜこのように頼むのか

完成案だけを見ても、入れる予定だった情報の抜けは分かりません。予定した項目と元資料を渡し、確認結果を先に受け取ると、どこを修正するかを人が判断しやすくなります。

■ 試した後に振り返ること

試した例について、次の点を振り返ってみてください。

・AIに何を作成・更新・確認してもらったか
・作成・更新する対象、書き方の見本、内容の根拠を分けて渡せたか
・変えてほしくない部分を伝えられたか
・結果を元資料と比べ、何を修正または確認したか

一度の依頼で仕上げる必要はありません。結果を見ながら、「この条件を残してください」「この部分だけ直してください」と追加で頼み、確認できた内容を資料へ反映していきましょう。

■ 自分の業務へ置き換えるには

まず、困っている作業が、説明、更新、要約、追記、形式の統一、照合のどれに近いかを選びます。選んだ例の資料名、入力欄、変更する項目、残す条件を、まとめて置き換えてください。

・短い説明文：社内サービスの案内を、サービス紹介や作業依頼に置き換えられます。読む人と、理解してほしいことや依頼したいことを指定します。
・情報の更新：会議案内を、当番表や作業予定に置き換えられます。日程、担当、場所など、変更してよい項目を指定します。
・要約：手順書を、調査報告や会議記録に置き換えられます。会議記録なら「決定事項、未決事項、次の行動」を残すなど、読む目的に合わせて残す情報を変えます。
・項目の追加：活動報告を、引き継ぎ資料や説明資料に置き換えられます。追加位置と、既存部分を変えてよい範囲を指定します。
・形式の統一：進捗メモを、問い合わせ記録に置き換えられます。項目も「問い合わせ内容、受付日、担当、対応状況、次の対応」などに変え、元の記録名を残します。
・照合：どの資料でも、完成案に加えて、元資料と必ず入れる予定だった項目を渡します。

■ 今回の練習の完了基準

自分の資料で一例を実行し、次の3点を説明できれば、今回の練習は完了です。実務で未確認事項が残った場合は、確認前の資料を完成版として共有せず、誰に何を確認するかを決めます。

・作成・更新する対象と、根拠や見本に使った資料の役割。
・AIの結果を元資料と照合し、採用・修正した内容とその理由。
・残った確認事項と、その確認先。残っていなければ、何を確認して完了と判断したか。

例えば会議案内の更新なら、「確定情報どおりに日時と場所が変わり、変更対象外の議題は保たれた。参加方法が未確認なので、主催者へ確認してから共有する」と説明できれば、練習としては完了です。
