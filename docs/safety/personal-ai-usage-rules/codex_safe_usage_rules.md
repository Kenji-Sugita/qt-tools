# 個人で安全に使うための生成AI利用ルール

生成AIは、自分がやりたいことを実現しやすくする強力な道具です。その一方で、誤った変更や意図しない操作まで速く大きく進めてしまうおそれもあります。したがって、便利さだけを見るのではなく、権限を絞ること、作業対象を狭くすること、変更を戻せる準備をすること、そして変更内容を自分で確認することが重要です。基本は、広く自由に任せるのではなく、限定した範囲を確認しながら任せる運用です。

個人で生成AIを安全に使うための運用ルールは、次の10項目に整理できます。

1. 最初は「読むだけ」または「限定した編集」から始めます。
   いきなり強い権限で使わず、まずは影響範囲の小さい使い方から始めることが大切です。

2. 作業場所は専用のディレクトリーやブランチに分けます。
   関係のないファイルと作業を分けます。ただし、ディレクトリーやブランチを分けただけでは、他のファイルを読む権限は制限されません。実際のアクセス範囲はサンドボックス、OSの権限、連携サービスの権限で確認します。

3. 作業の前後でGitのチェックポイントを作ります。
   既存の未コミット変更と未追跡ファイルも確認し、必要なものは別途バックアップします。Gitだけでは外部送信、公開、削除済みの外部データなどは元に戻せません。秘密情報をチェックポイントへ含めないよう注意します。

4. 指示は曖昧にせず、対象と制約を明確に書きます。
   どのファイルを対象にするのか、何を変えてよいのか、何を変えてはいけないのか、完了条件は何かを明示します。

5. 大きな作業は、いきなり実装させず、先に計画を出させます。
   まず方針を確認してから実装に進むことで、思い込みによる大きな誤りを防ぎやすくなります。

6. 変更は必ず差分を見てから受け入れます。
   実行結果だけで判断せず、何がどう変わったのかを確認します。必要なテスト・表示確認も行い、確認済みと未検証を分けます。自分の考えと一致する説明や、AIの「確認済み」という返答だけを根拠にしません。

7. 外部への通信先と送信内容を必要な範囲に絞ります。
   検索や資料取得と、ファイル送信・投稿などを区別します。モデルへの入力送信、シェルの通信、ブラウザー、MCPなどは同じ設定だけで制御されるとは限りません。利用環境ごとの制御範囲を確認します。

8. 強い権限は、必要性と制御範囲を確認してから使います。
   信頼できるリポジトリーでも、依存物や外部から取得した内容の安全まで保証されるわけではありません。サンドボックスの制限と承認の方式は別に確認します。承認を省略する設定だけでアクセス範囲が決まるわけではありません。

9. プロジェクト固有の設定や `.codex`、スキルを確認してから使います。
   そのプロジェクトにどのような前提や自動処理が含まれているかを、先に把握しておくことが重要です。

10. MCPなどの外部連携は、接続先・権限・操作の影響に応じて確認を残します。
    読み取り専用の参照、更新、送信、削除を区別し、不要なツールや権限は与えません。通常の参照まで毎回止めることと、重要な外部操作を確認することは分けます。シェルの制限がMCPの操作にもそのまま適用されると思い込まないようにします。

生成AIには、対象と完了条件を明確にして任せ、権限・実際の変更・外部への影響を確認します。指示文は作業上のルールであり、技術的なアクセス制限の代わりにはなりません。
