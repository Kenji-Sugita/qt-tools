# architecture -> design コンサルティング結果

## 対象

概要設計書から詳細設計書群へ分解する工程を対象とする。

## 要約

- AI は構成要素を UI、描画、状態管理、設定、イベント処理へ具体化する支援に向く。
- 人は操作仕様、描画挙動、例外系、ドキュメント分割の妥当性を決める。
- 自動化は中程度で、設計書分割と粒度調整に特に有効である。

## 入力

- 概要設計書
- UI 要件
- 描画要件
- Qt 利用方針

## 出力

- 詳細設計書群のたたき台
- UI 設計
- 描画設計
- 状態遷移や設定項目の整理

## AI の役割

- 概要設計の責務を詳細設計へ展開する
- 画面、操作、描画処理の観点を分離する
- 採用した UI 技術方針に合わせて設計粒度を揃える
- 設定項目と永続化対象の候補を整理する

## 人の役割

- 設計分割が過不足ないか判断する
- UI 操作仕様と体験の一貫性を確認する
- プラットフォーム差分を最小化する判断を行う
- 実装で無理のない粒度に整える

## 適用条件

- 概要設計で責務分担と主要制約が整理されている
- UI、描画、設定、状態の論点が識別できている

## 非適用条件

- 概要設計が抽象的すぎて詳細化の根拠が不足している
- Qt 固有制約を無視して一般 UI 設計へ流れる

## 自動化できる範囲

- 詳細設計書の見出し構成案
- 画面や描画観点の洗い出し
- 状態、イベント、設定項目の整理
- 設計間の参照関係の明示

## 自動化しにくい範囲

- 見た目や操作感の最終判断
- 微妙な描画仕様の採否
- ドキュメント分割の運用最適化

## Qt 固有の重点論点

- 採用した UI 技術に応じた描画責務と更新契機
- 入力イベント、ドラッグ、ダブルクリックなどの操作粒度
- High DPI、透過、最前面表示、プラットフォーム差分
- 永続化対象と非永続化対象の切り分け

## 推奨 LLM / 使い分け

- 構造化と分解が得意なモデル
  - 詳細設計書群の分割に使う
- UI 記述に強いモデル
  - 操作仕様と画面要素整理に使う
- 厳密なレビュー向きモデル
  - 設計間の矛盾検出に使う

## AI と既存自動化手段の役割分担

- AI
  - 詳細設計書群の分割、UI / 描画 / 設定観点の整理、設計間参照の明示を担う
- 人
  - UI 体験、描画挙動、プラットフォーム差分、実装粒度の最終判断を担う

## プロンプト設計方針

- 概要設計の各責務を個別に展開させる
- UI、描画、設定を別セクションで出力させる
- 設計対象外も明示させる
- Qt 前提と禁止事項を冒頭で固定する

## 導入段階

- PoC
  - 1 画面または 1 機能を対象に詳細化の粒度を検証する
- 限定導入
  - UI、描画、設定の分割観点を実案件で運用する
- 本格導入
  - 詳細設計テンプレートとレビュー観点を標準化する

## KPI

- 詳細設計初稿作成時間
- 設計間の矛盾指摘件数
- 実装時の設計差し戻し件数

## 顧客提案時の訴求点

- 概要から実装可能な粒度へ素早く落とせる
- 文書分割によりレビューしやすくなる
- 人は体験品質と妥当性確認に集中できる
