# パイプライン成功率メモ

今の状態だと、文書生成チェーンが最後まで大きく破綻せず流れる確率は、概算で `60%` から `80%` くらいです。

## 段階ごとの見積もり

- `request -> requirements`
  - `80%` から `90%`
- `requirements -> architecture`
  - `80%` 前後
- `architecture -> design`
  - `75%` から `85%`
- `design -> implementation`
  - `50%` から `70%`
- `implementation -> verification`
  - `60%` から `75%`

## 全体成功率が下がる理由

- 後段ほど自由度が高い
- コード構成の具体度がまだ足りない
- `implementation` と `verification` のテンプレートが未整備
- 検証結果ファイルの書き分けがまだ抽象的

## 成功率を上げる方法

- `implementation` 用テンプレートを追加する
- `verification` 用テンプレートを追加する
- 各工程の入力と出力をさらに固定する
- 一度 end-to-end で流して詰まる点を修正する

## 現時点の評価

上流文書生成はかなり通るが、アプリ完成まで含めた全体成功率はまだ `70%` 前後と見るのが妥当。

一度通しで試して修正すれば、`80%` 台までは上げやすい。
