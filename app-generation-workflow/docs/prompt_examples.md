# AI 指示プロンプト例

この文書は、`app-generation-workflow` を使うときに AI へ貼り付けるためのプロンプト例をまとめたものである。

プロンプト例では、日本語の作業名とファイル名を併記する。
日本語の作業名で意図を伝え、ファイル名で作業対象を明確にする。

## 1. 最初にワークフローを読ませる

```text
app-generation-workflow/three_key_documents_workflow.md を読んでください。
このワークフローに従って、要求、仕様化前ノート、三点セット、実装プロンプト、実装の順に作業してください。
```

## 2. requirement.txt を作る

```text
任意形式の要求 .txt をもとに、対象アプリ用ディレクトリを作成してください。

要求定義（requirement.txt）を作成してください。
未決事項を減らすため、テンプレートは app-generation-workflow/templates/requirement.txt を使ってください。
作成先は対象アプリ用ディレクトリの requirement.txt です。

要求 .txt から、目的、利用者、アプリ種別、やりたいこと、入力、表示・出力、主な操作、守るべきルール、エラー・例外・境界値、代表例と期待結果、対象外、未決事項を整理してください。
不足している内容は、AI が推測で埋めず、確認事項として分けてください。
```

## 3. 要求定義レビューをする

```text
要求定義（requirement.txt）をレビューしてください。

仕様化前ノートを作る前に、次を確認してください。
- 目的、利用者、アプリ種別が分かるか。
- 入力、表示・出力、主な操作が分かるか。
- 守るべきルール、エラー・例外・境界値が分かるか。
- 代表例と期待結果があるか。
- 作らない機能が分かるか。
- 未決事項が三点セット生成を止める内容か。
- AI が推測で補いそうな箇所があるか。

不足がある場合は、次の形で出してください。
- ユーザーへ確認した方がよい点
- requirement.txt への追記候補
- 三点セット生成前に必須の確認
- 実装前までに決めればよい確認
- 今回は対象外にできる確認

AI の追記候補は推薦案として扱い、ユーザーが採用するまで正式な要求にしないでください。
実装や三点セット生成に影響する不足がある場合は、仕様化前ノートへ進まず警告してください。
```

## 4. 仕様化前ノートを作る

```text
レビュー済みの要求定義（requirement.txt）をもとに、仕様化前ノートを作成してください。

仕様化前ノート（source_memo.md）を作成してください。
テンプレートは app-generation-workflow/templates/source_memo.md を使ってください。
作成先は対象アプリ用ディレクトリの source_memo.md です。

requirement.txt から、目的、利用者、アプリ種別、やりたいこと、入力、表示、ルール、対象外、未決事項を整理してください。
アプリ種別を1つ選び、代表例と期待結果も記載してください。

未決事項は次の1行形式で記載してください。
- 未決事項: <決めること>。決定後の反映先: <章名>
```

## 5. 仕様化前ノートをレビューする

```text
仕様化前ノート（source_memo.md）をレビューしてください。

次を確認してください。
- 要求 .txt の内容が漏れなく反映されているか。
- 目的、利用者、入力、表示、操作、対象外が整理されているか。
- 未決事項が1行形式で書かれているか。
- 未決事項と本文の断定仕様が矛盾していないか。
- 三点セット作成へ進める状態か。

AI で確認できる矛盾、抜け、推測、未決事項を列挙してください。
人が判断すべき項目は、採用判断または要確認として分けてください。
```

## 6. 逆生成レビュー用仕様化前ノートを作る

```text
既存実装、生成済み三点セット、またはコードをもとに、逆生成レビュー用仕様化前ノートを作成してください。

逆生成レビュー用仕様化前ノート（source_memo_reverse_review.md）を使って、対象アプリ用の仕様化前ノート（source_memo.md）を作成してください。
テンプレートは app-generation-workflow/templates/source_memo_reverse_review.md を使ってください。
作成先は対象アプリ用ディレクトリの source_memo.md です。

現行実装から読み取れる挙動、仕様として採用する挙動、バグ候補・要確認事項を分けて記載してください。
実装由来の挙動を、いきなり正式仕様として書かないでください。

境界値、代表例、期待結果、根拠ルール、採用判断を整理してください。
```

## 7. 5分割仕様化前ノートを使う

```text
対象アプリの規模が大きいため、5分割仕様化前ノートを作成してください。

単一の仕様化前ノート（source_memo.md）は作らず、five_source_memos/ 配下に分割ノート群を作成してください。

次の構成で整理してください。
- five_source_memos/index.md
- five_source_memos/shared.md
- five_source_memos/01_purpose_scope.md
- five_source_memos/02_input.md
- five_source_memos/03_business_logic.md
- five_source_memos/04_ui_operation.md
- five_source_memos/05_test_examples.md

要求 .txt の内容を、目的、入力、業務ルール、UI・操作、代表例、共通事項に分けて整理してください。
未決事項は、該当する分割ノートまたは index.md に記載してください。
```

## 8. 三点セットを作る

```text
仕様化前ノート（source_memo.md）をもとに、三点セットを作成してください。

作成先は次の3ファイルです。
- specs/01_usecase_spec.md
- specs/02_ui_spec.md
- specs/03_business_spec.md

テンプレートは次を使ってください。
- app-generation-workflow/templates/01_usecase_spec.md
- app-generation-workflow/templates/02_ui_spec.md
- app-generation-workflow/templates/03_business_spec.md

仕様化前ノートのアプリ種別を三点セットへ引き継いでください。
不要な任意パターンは、対象外またはなしとして整理してください。
作成した三点セットは草案として扱い、実装プロンプト作成前にレビューしてください。
```

## 9. 三点セットをレビューする

```text
三点セットをレビューしてください。

対象ファイルは次の3ファイルです。
- specs/01_usecase_spec.md
- specs/02_ui_spec.md
- specs/03_business_spec.md

AI で確認できる、形式、空欄、矛盾、抜け、推測、未決事項、バグ候補を列挙してください。
仕様化前ノート（source_memo.md）または5分割仕様化前ノートの内容が、三点セットへ反映されているか確認してください。

人が判断すべき採用判断、業務判断、安全性、対象外、移植方針は、要確認として分けてください。
レビュー済みでない三点セットから、実装プロンプトやソースコードを作成しないでください。
```

## 10. 実装プロンプトを作る

```text
レビュー済み三点セットを上位仕様として、実装プロンプトを作成してください。

実装プロンプト（implementation_prompt.md）を作成してください。
テンプレートは app-generation-workflow/templates/implementation_prompt.md を使ってください。
作成先は対象アプリ用ディレクトリの prompts/implementation_prompt.md です。

実装方式、ビルド方式、テスト方式、UI条件、保存・永続化条件、対象外、実装前に確認すべき未決事項を記載してください。
実装時の作業ディレクトリは対象アプリ用ディレクトリとしてください。
対象アプリ用ディレクトリに implementation_constraints.md が存在する場合は、プロジェクト共通の実装制約として実装プロンプトへ参照を記載してください。
実装制約の詳細を source_memo.md や三点セットへ重複記述しないでください。
実装プロンプトでは、標準ではテストコード生成を指示しないでください。
コード生成後に自動テストを追加できるよう、ビジネスロジックを UI に依存しない形にする指示を入れてください。
実装プロンプトが使える状態になっていない場合は、実装へ進まず警告してください。
```

## 11. 実装プロンプトをレビューする

```text
実装プロンプト（prompts/implementation_prompt.md）をレビューしてください。

次を確認してください。
- レビュー済み三点セットを参照しているか。
- 実装時の作業ディレクトリが対象アプリ用ディレクトリになっているか。
- implementation_constraints.md が存在する場合、実装プロンプトから参照しているか。
- 実装制約を source_memo.md や三点セットへ混ぜていないか。
- 実装方式、ビルド方式、テスト方式が記載されているか。
- テストコード生成ではなく、コード生成後にテストを追加しやすい構造を指示しているか。
- 対象外が明記されているか。
- 未決事項が残っていないか、または実装前に確認すべき事項として列挙されているか。
- 三点セットにない仕様を追加していないか。

不足がある場合は、実装へ進まず警告してください。
```

## 12. コード生成後にテストを作成する

```text
コード生成後のテストを作成してください。

次を参照してください。
- source_memo.md
- specs/01_usecase_spec.md
- specs/02_ui_spec.md
- specs/03_business_spec.md
- prompts/implementation_prompt.md
- include/
- src/

三点セット、実装プロンプト、実装コードを照合し、自動テストと手動確認項目を分けて作成してください。
コードだけから期待値を作らないでください。
実装コードが仕様と違う場合は、テストに合わせて固定せず、不整合として列挙してください。

自動テストでは、入力検証、データ正規化、主要な業務ルール、境界値、例外またはエラーケース、状態遷移、回帰しやすい計算や判定を優先してください。
UI の見た目、操作感、表示崩れ、端末差、外部連携、参照画像との対応は、手動確認項目として整理してください。

作成したテスト、未作成のテスト、手動確認が必要な項目、仕様との不整合を報告してください。
```

## 13. 実装結果をレビューする

```text
実装結果をレビューしてください。

実装が、実装プロンプト（prompts/implementation_prompt.md）と三点セットに従っているか確認してください。

次を参照してください。
- source_memo.md
- specs/01_usecase_spec.md
- specs/02_ui_spec.md
- specs/03_business_spec.md
- prompts/implementation_prompt.md
- include/
- src/
- tests/

次を確認してください。
- 三点セットに書かれた仕様が実装されているか。
- 三点セットにない便利機能を勝手に追加していないか。
- 未決事項を勝手に仮決めしていないか。
- UI仕様と画面の挙動が合っているか。
- ビジネスレイヤー仕様と検証、計算、保存、状態変更が合っているか。
- エラー表示や例外条件が合っているか。
- コード生成後に作成したテストが仕様から導ける内容になっているか。
- コードに直接現れない仕様根拠、参照画像、外部参照資産、手動確認対象が後続文書で落ちやすい状態になっていないか。
- 実装中に決めたことを仕様へ戻しているか。

不整合、不足、仕様への反映漏れ、後続の implementation_design_contract.md と app_design.md 作成時に注意すべき点を列挙してください。
重大な不整合、仕様への反映漏れ、未解決の仮決めがある場合は、implementation_design_contract.md や app_design.md を作成しないでください。
コードや仕様は、このレビュー指示だけでは修正しないでください。
```

## 14. 仕様へ戻す

```text
実装結果レビューで見つかった不整合、仕様への反映漏れ、未解決の仮決めを確認してください。

コードを直接修正せず、まず次のどこへ反映すべきかを整理してください。
- source_memo.md
- specs/01_usecase_spec.md
- specs/02_ui_spec.md
- specs/03_business_spec.md
- prompts/implementation_prompt.md
- include/
- src/
- tests/

正式な仕様として採用する内容、コードを修正すべき内容、残リスクとして記録すべき内容を分けて列挙してください。
未解決の重大な不整合がある場合は、implementation_design_contract.md や app_design.md を作成しないでください。
```

## 15. 実装設計契約を作る

```text
実装結果レビューで重大な不整合がないことを確認した後、三点セットとレビュー済みの実装コードをもとに、実装設計契約を作成してください。

実装設計契約（implementation_design_contract.md）を作成してください。
作成先は対象アプリ用ディレクトリの implementation_design_contract.md です。

次を参照してください。
- source_memo.md
- specs/01_usecase_spec.md
- specs/02_ui_spec.md
- specs/03_business_spec.md
- prompts/implementation_prompt.md
- 実装結果レビューの指摘
- include/
- src/
- tests/

implementation_design_contract.md には、三点セットと実装コードの対応を追跡できる形で記載してください。
コードに直接現れない仕様根拠、UI仕様、デザイン方針、参照画像、外部参照資産、手動確認対象も省略しないでください。
特に specs/02_ui_spec.md に参照画像や外部資産パスがある場合は、UI契約または手動確認対象にパス付きで明記してください。

次を含めてください。
- 実装方式
- ターゲット構成
- ソース構成
- UI契約
- ビジネスロジック契約
- テスト契約
- 自動テスト対象
- 手動確認対象
- 対象外
- 残リスク

三点セットにない仕様を追加しないでください。
コードが三点セットと矛盾している場合は、契約として確定せず、不整合として列挙してください。
未解決の重大な不整合がある場合は、implementation_design_contract.md を完成扱いにしないでください。
```

## 16. アプリ設計書を作る

```text
三点セット、実装設計契約、レビュー済みの実装コードをもとに、アプリ設計書を作成してください。

アプリ設計書（app_design.md）を作成してください。
作成先は対象アプリ用ディレクトリの app_design.md です。

次を参照してください。
- source_memo.md
- specs/01_usecase_spec.md
- specs/02_ui_spec.md
- specs/03_business_spec.md
- prompts/implementation_prompt.md
- implementation_design_contract.md
- 実装結果レビューの指摘
- include/
- src/
- tests/

app_design.md には、実装後に確定したアプリ全体の設計を記載してください。
三点セットの内容を単に要約せず、仕様根拠を追跡できる形で反映してください。
コードに直接現れない仕様根拠、UI仕様、デザイン方針、参照画像、外部参照資産、手動確認対象も省略しないでください。
特に specs/02_ui_spec.md に参照画像や外部資産パスがある場合は、画面設計または参照仕様にパス付きで明記してください。

次を含めてください。
- 概要
- 参照仕様
- 対象範囲
- システム構成
- アーキテクチャ方針
- 画面設計
- データ設計
- ビジネスルール
- クラス設計
- エラー設計
- テスト設計
- ビルド・実行設計
- 変更時のルール
- 残リスク
- 運用方針

三点セット、実装設計契約、コードの間に矛盾がある場合は、設計書へ断定的に取り込まず、不整合として列挙してください。
未解決の重大な不整合がある場合は、app_design.md を完成扱いにしないでください。
```

## 17. アプリ設計書をレビューする

```text
アプリ設計書（app_design.md）をレビューしてください。

app_design.md が、三点セット、implementation_design_contract.md、レビュー済みの実装コードを正しく反映しているか確認してください。

次を参照してください。
- source_memo.md
- specs/01_usecase_spec.md
- specs/02_ui_spec.md
- specs/03_business_spec.md
- prompts/implementation_prompt.md
- implementation_design_contract.md
- app_design.md
- include/
- src/
- tests/

次を確認してください。
- 三点セットの内容が app_design.md に反映されているか。
- implementation_design_contract.md の内容が app_design.md に反映されているか。
- 実装コードの構成、責務、主要処理が app_design.md に反映されているか。
- 参照画像、外部参照資産、デザイン方針、手動確認対象がパス付きで明記されているか。
- 既知差分が確定仕様として扱われていないか。
- 未テスト項目が落ちていないか。
- 三点セットにない仕様を追加していないか。
- implementation_design_contract.md と矛盾していないか。
- app_design.md 内で同じ仕様について矛盾した記述がないか。

問題がある場合は、修正対象のファイルと修正方針を列挙してください。
このレビュー指示だけでは、app_design.md やコードを修正しないでください。
```

## 18. 意図違いを修正する

このプロンプトは通常フローで毎回使うものではない。
実装レビュー、テスト、手動確認などで問題や仕様との不一致が判明したときに使う。

```text
実装結果が意図と違います。

コードを直接修正せず、まず仕様化前ノート（source_memo.md）のどこを修正すべきか確認してください。
5分割仕様化前ノートを使っている場合は、該当する分割ノートを確認してください。

修正は次の順に進めてください。
1. 仕様化前ノートを修正する。
2. 三点セットを修正する。
3. 実装プロンプトを修正する。
4. コードを修正する。
5. 仕様への反映漏れがないか確認する。

各段階でレビューしてから次へ進んでください。
```
